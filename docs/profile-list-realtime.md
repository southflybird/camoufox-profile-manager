# 配置列表实时同步和桌面偏好

配置提交成功后通过 `GET /api/v1/events`（兼容 `/api/events`）通知打开的列表。使用已有 Cookie 或 `X-API-Key` 鉴权，不接受 URL 中的密钥。

SSE 帧：

- `change`：JSON 包含 `sequence`、`profile_id`。客户端通过已有详情接口重新读取并替换该配置；404/403 移除列表行。
- `reset`：重新同步完整列表，用于连接建立、分组/权限变更及订阅队列溢出。
- `denied`：会话失效或维护阻止访问，客户端停止订阅并重新校验登录。

通知不包含完整配置或凭据；配置 ID 按当前可见权限过滤。订阅每秒检查权限并发送心跳，约五分钟轮换连接。通知进程内有效，不支持多 worker 和历史重放。直接修改数据库文件不保证实时通知；前台每 60 秒及窗口获得焦点时重新校准。批量通知合并后刷新，单条通常只重新读取详情。关闭桌面时先通知事件流退出，再关闭服务，长连接不占用维护锁。

默认创建时间倒序，排序值相同时以创建时间倒序、ID 升序稳定排列。旧保存视图默认值不变；显式链接或选中的保存视图优先于个人偏好。排序和列显隐按用户隔离，桌面端保存在应用数据目录的 `desktop-state.json`，普通浏览器使用本地存储。窗口位置、尺寸、最大化状态也保存在该文件。该文件不包含登录密码。

名称和备注旁的铅笔按钮打开单字段编辑弹窗，复用 `PUT /profiles/{id}`，提交字段及 `row_version`。并发冲突保留草稿，用户可加载最新内容或再次确认保存。名称最多 255 字符、备注最多 1000 字符。名称 Enter 保存；备注 Ctrl+Enter 保存。

IP及位置显示最近一次成功启动浏览器时使用的出口 IP 和国家/地区。启动时复用生成动态指纹的检测结果（代理和直连均适用），只有浏览器启动成功后才写入 `last_browser_exit` 并通过 SSE 更新列表；启动中、失败或取消均保留上次成功记录。从未成功启动的配置显示“尚未启动”。

API、编辑页面、代理库批量分配及同步更换代理均保留实际出口，只增加“代理已更改”提示；悬停可查看上次成功启动时间及“将在下次成功启动后更新”。即使浏览器运行期间修改配置，列表仍表示该浏览器实际使用过的出口。代理检测结果保存在独立的 `proxy_check` 诊断记录中：编辑弹窗就地显示，列表单条/批量检测打开独立报告，不修改实际出口。整行编辑不写启动历史，避免旧编辑快照覆盖刚启动得到的新 IP。

升级时保留已有使用记录中可用的历史出口。由于旧版本混用了手动检测与启动结果，这类记录悬停显示“上次出口记录”，直到下一次成功启动后替换；不会把旧时间冒充成功启动时间。克隆、导入的新环境不继承来源环境的启动出口。无时区历史时间保持原墙上时间；带时区偏移的值显示为本机时间。

桌面“记住用户名和密码”只在登录成功后保存，取消勾选清除，不自动登录。Windows 使用 Credential Manager，其他平台使用原生 Keychain/Secret Service；存储不可用时不降级为明文文件。凭据槽按应用数据目录隔离，启动端口变化不影响恢复。
